## drizzle-kit config note

In drizzle-kit v0.28, a `driver: "neon-http"` field was required. In v0.31.10, the `driver` field is reserved only for `aws-data-api` and `pglite`. For PostgreSQL + neon, only `dialect: "postgresql"` + `dbCredentials: { url }` is needed. `drizzle-kit generate` does not require a live DB connection; the `dbCredentials.url` is used only by `drizzle-kit migrate` and `drizzle-kit push`.

## Migration file name

drizzle-kit auto-generates a random slug: `0000_glossy_vertigo.sql` (equivalent to the `0000_init.sql` placeholder in the plan). This is the correct and canonical migration file.

## Notes

- The Proxy-based lazy `db` export in `client.ts` ensures no module-import-time crash. The stub returned in test env is safe because schema tests never call any DB methods — they only call `getTableColumns()` on the raw schema objects.
- `drizzle.config.ts` falls back to a placeholder URL when `DATABASE_URL` is unset (for local dev without a Neon branch); `generate` ignores credentials.
- No `console.*` in production code — logger is available in `lib/logger.ts` for future diagnostics.
- Migration runner (applying migrations to environments) is explicitly deferred per ADR-0005.
